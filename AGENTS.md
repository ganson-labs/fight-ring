# Ринг моделей: инструкция для агента-разработчика

Ты работаешь в репозитории «Ринг моделей». Это 2D-файтинг, где бойцов делают нейросети: каждая модель придумывает персонажа, рисует ему тело, записывает голос, выбирает приёмы из общего набора и пишет мозги, которые ведут бой. Проект открытый, лицензия MIT. Документы для людей лежат в `README.md` и в `docs/`, начни с `docs/architecture.md`.

В этом тексте три слова значат одно и то же везде. Судья — программа в `ring.mjs` и `judge/`, которая заводит участников, считает бои и собирает ролики. Участник — модель, которая строит бойца в отдельной папке вне репозитория. Оператор — человек, который запускает судью на своей машине.

## Как устроен репозиторий

`kit/` — набор участника. Он целиком копируется в папку каждого участника. Внутри лежат правила для модели `ARENA.md`, шаблон бойца `fighter/` и папка `arena/`: движок (`engine/`), отрисовка (`render/`), инструменты участника (`tools/`, вход через `cli.mjs`), звуки, библиотеки отрисовки и шрифт (`vendor/`).

`judge/` — судья. `contestants.js` заводит участников и пишет скрипты запуска агентов, `run.js` запускает агента без человека, `match.js` ведёт матч и раздевалку, `bench.js` играет лигу, `render.js`, `reel.js` и `pack.js` делают ролики, `gamedata.js` собирает данные для игры, `publish.js` и `site.js` публикуют сезон и собирают сайт.

`viewer/` — игра в браузере, `serve.mjs` — её сервер. `site/` — страницы сайта на Astro: главная, турнир, бойцы; данные они читают из `seasons/` при сборке. `seasons/` — опубликованные турниры: бойцы по версиям и записи раундов. `tests/` — тесты. `prompts/` — промпты, которые получают модели-участники.

Рабочие файлы судьи в git не попадают: `contestants.json`, `launch/`, `matches/`, `leagues/`, `ledger/`, `out/`, `dist/`.

## Команды

```
npm test                                  # все тесты, около двух минут; нужны Chrome и ffmpeg
node --import ./tests/free.mjs --test tests/engine.test.mjs   # один файл тестов
node serve.mjs --port 4861                # игра; порт 4848 по умолчанию может быть занят
node kit/arena/cli.mjs check kit/fighter  # проверка одного бойца
node kit/arena/cli.mjs spar <папка бойца> --vs <папка бойца>   # бой двух бойцов без браузера
node ring.mjs help                        # все команды судьи
node ring.mjs site dist                   # сайт обычными файлами
```

Тесты нужно запускать именно через `npm test` или с ключом `--import ./tests/free.mjs`: этот файл включает набор правил ринга 3, на котором написаны старые тесты. Тесты ринга 4 сами включают свой набор.

## Что нельзя ломать

### Записи боёв воспроизводятся

Бой задан зерном, стартом и действиями обоих бойцов на каждом тике. Тот же вход всегда даёт тот же хэш боя, в Node и в браузере. В `seasons/` лежат записи турнира, и они играются сегодняшним движком: у них нет своей копии движка.

Поэтому не меняй ход боя в `kit/arena/engine/`. Ходом боя считается всё, от чего может измениться хоть один тик уже записанного боя: числа в `constants.js` и `standard.js`, порядок действий в `sim.js`, проверка бойца, счёт шагов мозгов в `instrument.js` и `meter.js`. Можно менять то, что на бой не влияет: тексты ошибок, комментарии, новые функции, которые старый бой не вызывает.

Проверка: `node --test tests/season.test.mjs` переигрывает каждый раунд сезона и сверяет хэш. Если тебе кажется, что задача требует изменить ход боя, остановись и спроси владельца: это решение о новой версии ринга, а не правка.

Не меняй файлы в `seasons/`. Бойцы и слова моделей лежат там как есть.

В движке нет `Math.random`, времени и ничего, что зависит от машины. Случайность берётся только из зерна боя. Движок не обращается к DOM: он должен работать в Node, в браузере и в потоке Worker.

### Участник изолирован

Участник не должен знать ни пути к репозиторию, ни другого участника, ни файлов судьи. Его агент не должен получать настройки, память и навыки оператора.

Поэтому в `kit/` нельзя класть ничего, что ссылается на файлы вне `kit/`: набор копируется в чужую папку и должен работать там сам. Нельзя писать в папку участника пути к репозиторию. Агента участника запускает только скрипт `launch/<id>.sh` или `launch/<id>.ps1`, который пишет `judge/contestants.js`; не добавляй другие способы запуска в обход него.

Скрипт запуска существует в двух видах, для Windows (PowerShell) и для macOS и Linux (bash). Меняя один, меняй и второй с тем же смыслом, и поправь тесты обоих в `tests/launch.test.mjs`.

Проверка: `node --import ./tests/free.mjs --test tests/launch.test.mjs`.

### Настоящих агентов не запускай

Команды `node ring.mjs run …`, `bash launch/<id>.sh`, кнопки пульта «Турнир» и команды `match comment` и `match reel` без ключа `--no-model` запускают платные модели на подписке владельца. Не запускай их без прямой просьбы владельца. То же относится к `paint` и `voice` из инструментов набора: они тратят картинки и секунды голоса.

Запуск агента проверяется подставным агентом: скрипт с именем `claude`, `codex` или `agy` ставится первым в `PATH`. Готовый пример лежит в `tests/launch.test.mjs`.

### Зависимостей нет

У движка, набора, судьи и игры нет `node_modules` и нет шага установки. Не добавляй пакеты из npm в `kit/`, `judge/`, `viewer/` и в корневой `package.json`. Единственное место с зависимостями — страницы сайта в `site/` (Astro, свой `package.json`); команда `node ring.mjs site dist` ставит их сама. Если нужна возможность, сначала поищи её в Node.js и в коде проекта: браузером управляет `kit/arena/tools/browser.js`, PNG читает и пишет `kit/arena/tools/png.js`, файлы отдаёт `kit/arena/tools/serve.js`.

Страницы игры и лаборатории ничего не берут из сети: библиотеки и шрифт лежат в `kit/arena/vendor/`. Это проверяет `tests/repo.test.mjs`.

## Как проверять свою работу

После правки кода запусти тесты, которые относятся к изменённому месту, а перед тем как сказать «готово», запусти `npm test` целиком.

После правки игры или отрисовки открой затронутый экран в настоящем браузере и посмотри на него сам. Запусти `node serve.mjs --port <свободный порт>`, открой страницу через `launch()` из `kit/arena/tools/browser.js`, сохрани снимок и проверь `page.console`: там не должно быть ошибок. Экраны открываются по адресу: `/?screen=matches`, `/?screen=play`, `/?match=t51-final&round=1&auto=round`; полный список есть в `docs/game.md`.

После правки съёмки роликов запусти `node --test tests/clip.test.mjs`. Он снимает один бой двумя способами и сравнивает кадры. Если он падает, ищи причину в отрисовке, а не ослабляй порог: так уже нашлась гонка загрузки шрифта.

Если проверка не удалась или ты её не делал, скажи об этом прямо и назови, что осталось непроверенным.

## Что не попадает в репозиторий

Не клади в репозиторий пути домашних папок, имена аккаунтов, токены и ключи. Настройки сервисов оператора лежат вне репозитория в `~/.config/fight-ring/`. Материалы спонсоров в репозиторий не кладутся: в `ads/` лежит только образец без брендов `ads/demo/`.

Каждый новый звук, картинка или шрифт должен получить запись о происхождении и лицензии: звук в `kit/arena/sounds/README.md` (его пишет `scripts/build-sounds.mjs`), остальное в `ASSETS.md`. Тест `tests/repo.test.mjs` проверяет, что запись есть у каждого звука.

## Как писать

Код и комментарии в коде пишутся по-английски, тексты для людей и сообщения программ пишутся по-русски. Комментарий объясняет, почему сделано так, и по возможности называет случай, из-за которого это появилось.

Документы пиши простыми словами и полными предложениями, абзацами. Список используй только для перечисления. Команду вноси в README и в `docs/` только после того, как сам её запустил.

Коммить по ходу работы, сообщение коммита пиши по-русски: что изменилось и зачем. Не отправляй изменения на сервер и не создавай запросы на слияние без просьбы владельца.

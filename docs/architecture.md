# Устройство

## Папки

- `kit/` — набор участника. Он целиком копируется в папку каждого участника, поэтому в нём нет ничего, что знает о судье. Внутри лежат правила `ARENA.md`, шаблон бойца `fighter/` и папка `arena/`.
- `kit/arena/engine/` — правила боя. Движок детерминирован и не знает о браузере: 60 тиков в секунду, случайность только с зерном. Им пользуются судья, инструменты участника и игра.
- `kit/arena/render/` — отрисовка на PixiJS 8 (WebGL): сцена, скелет с частями тела, эффекты, камера, табло, экраны VS и итога, выбор звуков.
- `kit/arena/tools/` — инструменты участника: `check`, `spar`, `league`, `preview`, `look`, `paint`, `parts`, `voice`, `limits`. Вызываются через `kit/arena/cli.mjs`.
- `kit/arena/sparring/` — спарринг-партнёры ринга: тринадцать бойцов с разными привычками и манекен.
- `kit/arena/sounds/`, `kit/arena/vendor/` — звуки ринга, библиотеки отрисовки и шрифт.
- `judge/` — судья: участники и запуск агентов, матч и раздевалка, лига, ролики, протокол, сезон и сайт. Команды судьи собраны в `ring.mjs`.
- `viewer/` — игра. `serve.mjs` — её сервер.
- `stages/` — сцены, `announcer/` — ведущий, `commentator/` — голоса комментаторов, `ads/` — образец рекламных заготовок.
- `prompts/` — промпты участникам и комментатору. Текст промпта начинается после строки `---`.
- `seasons/` — опубликованные турниры.
- `tests/` — тесты и их данные в `tests/fixtures/`.
- `scripts/` — разовые скрипты автора: сборка звуков, показ для ролика, разбор лиги.
- `docs/` — эти документы; `docs/v3/` — история правил ринга 3.0.

Рабочие файлы судьи в git не попадают: `contestants.json`, `launch/`, `matches/`, `leagues/`, `ledger/`, `out/`, `dist/`.

## Движок

Главные файлы движка: `constants.js` содержит все числа, `skeleton.js` содержит общий скелет и позы, `standard.js` содержит набор приёмов ринга 4 и переключатель наборов правил, `fighter.js` проверяет бойца, `sim.js` ведёт бой и собирает то, что видят мозги, `commands.js` назначает команды приёмов для игры человеком, `version.js` хранит версию ринга.

В ринге 4 приёмы у всех бойцов из одного набора с одинаковыми числами. Боец отличается телосложением (12 очков на здоровье, силу, скорость и защиту), выбором шести спецприёмов и суперприёма из набора, обликом и голосом и мозгами. Мозги — это файл `brain.js` с функцией, которую ринг вызывает каждый тик.

Движок помнит и правила ринга 3: набор правил `free`, где боец собирался из блоков с ценами и мог писать способности кодом (`blocks.js`, `ability.js`, `measure.js`). Код мозгов и способностей выполняется со встроенным счётчиком шагов (`instrument.js`, `meter.js`): предел задан в шагах, а не во времени, поэтому бой не зависит от скорости машины. На наборе `free` идут тесты рингов 2 и 3 и старые матчи; для этого тесты запускаются с файлом `tests/free.mjs`.

Версию ринга хранит `kit/arena/engine/version.js`. В ней четыре числа: `engine` меняется, когда меняется ход боя; `rules` меняется, когда меняется то, что может написать участник; `tools` меняется, когда меняются инструменты и показ; `ring` — общий номер.

## Три правила, на которых всё держится

**Запись боя воспроизводится.** Бой задан зерном, стартом и действиями бойцов на каждом тике. Один и тот же вход даёт один и тот же хэш боя в Node и в браузере. На этом стоят сезоны в репозитории, проверка матча и повторы в игре. Судья хранит с каждым раундом снимок движка, поэтому матч на диске проигрывается и после изменения движка. У сезона в репозитории такого снимка нет: он воспроизводится сегодняшним движком, и менять ход боя в `kit/arena/engine` нельзя, пока сезон должен играться.

**Участник изолирован.** Участник живёт в своей папке вне ринга и не знает ни пути к рингу, ни соседа. Агент запускается только скриптом запуска, который убирает следы сессии оператора и даёт чистый профиль. Подробности описаны в [contestants.md](contestants.md).

**У движка и набора нет зависимостей.** Движку, набору, судье и игре не нужны `node_modules` и установка. Движок, инструменты и судья написаны на чистом Node.js, браузером управляет собственный код по протоколу DevTools, библиотеки отрисовки и шрифт лежат в `kit/arena/vendor/`. Набор должен работать в папке участника сразу после копирования, без установки и без сети.

## Проверка

```
npm test
node kit/arena/cli.mjs check kit/fighter
```

Команда `npm test` запускает все тесты из `tests/`. Для тестов с роликами и страницами нужны Chrome и ffmpeg; без ffmpeg тест ролика пропускается. Полный прогон на ноутбуке занимает около двух минут. Те же тесты и сборку сайта запускает GitHub Actions (`.github/workflows/test.yml`).

Что проверяют тесты по файлам:

- `engine`, `ring3`, `ring4`, `abilities`, `commands`, `body`, `anchors`, `meter` — правила боя и проверку бойца;
- `season` — записи опубликованных сезонов воспроизводятся сегодняшним движком;
- `protocol` — запись ринга 2.0 воспроизводится на своём снимке движка;
- `launch` — папку участника и скрипты запуска на обеих системах, запуск через подставного агента;
- `run`, `judge`, `game`, `pack`, `voices` — судью: промпты, разбор раунда, версии бойцов, пакет для монтажа, учёт голосов;
- `clip`, `browser`, `screens` — съёмку роликов и экраны в настоящем браузере;
- `repo` — сам репозиторий: страницы не ходят в сеть, в файлах нет чужих домашних папок, у каждого звука записан источник.

Команда `check` проверяет одного бойца по правилам ринга 4; `kit/fighter` — шаблон набора, с которого начинает каждый участник. Так же проверяется любой боец сезона, например `node kit/arena/cli.mjs check seasons/2026-11-gpt-6-2/fighters/opus50/v5`.

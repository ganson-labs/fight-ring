# Как выставить свою модель

Здесь описано, как судья заводит участника, запускает ему агента и проверяет, что агент не выходил за свою папку. Человека, который это делает, документ называет оператором. Все команды судьи запускаются из папки ринга: `node ring.mjs <команда>`, полный список печатает `node ring.mjs help`.

Запуск настоящего агента тратит лимиты вашей подписки на Claude, ChatGPT или Gemini. Сборка бойца занимает у модели от получаса до полутора часов.

## Что нужно на машине оператора

Нужны Node.js 22 или новее, git, ffmpeg и ffprobe в `PATH` и Google Chrome, Chromium или Edge. Если браузер стоит в необычном месте, путь к нему задаёт переменная `RING_CHROME`. На macOS и Linux нужен bash, на Windows нужен PowerShell.

Нужен хотя бы один агент с выполненным входом: Claude Code (`claude`), Codex CLI (`codex`) или Antigravity CLI (`agy`) для моделей Gemini.

Картинки всем участникам рисует один и тот же генератор: встроенный инструмент картинок Codex CLI в профиле оператора. Поэтому Codex CLI с выполненным входом (`codex login`) нужен даже тогда, когда оба участника работают в Claude Code. Профиль для рисования по умолчанию лежит в `~/.codex`, другой задаёт `RING_PAINT_CODEX_HOME` в файле настроек сервисов.

Голос бойцам делает ElevenLabs, и запрос к нему идёт через ssh. В файле `~/.config/fight-ring/services.env` задаются две строки: `ELEVENLABS_SSH` с именем сервера для ssh и `ELEVENLABS_SSH_ENV` с путём к файлу на этом сервере, где лежит `ELEVENLABS_API_KEY`. На сервере нужен `python3`. Ключ читается только на сервере и не попадает ни на машину оператора, ни в папки участников. Строка `ELEVENLABS_SSH=off` выключает голос: участник получит понятный отказ и останется без реплик.

Лимиты на одного участника лежат в `ring.config.json` в разделе `limits`: 40 картинок, 3 голоса и 150 секунд речи. Отдельному участнику их меняет раздел `contestants.<id>.limits`. При создании участника лимиты копируются в его папку в `.ring/limits.json`. Остаток показывает команда `node arena/cli.mjs limits` в папке участника.

## Создать участника

```
node ring.mjs new red  --agent claude --model "Claude Opus 5.5" --agent-model claude-opus-5-5 --effort high --color "#e8825a"
node ring.mjs new blue --agent codex  --model "GPT-6.2"         --agent-model gpt-6.2         --effort high --color "#4fc3c9"
```

Ключ `--agent` выбирает агента: `claude`, `codex` или `gemini`. Ключ `--model` задаёт имя модели на экране. Ключ `--agent-model` задаёт идентификатор модели для агента: у Codex это один из тех, что печатает `codex debug models`, у Antigravity один из тех, что печатает `agy models`. Ключ `--effort` задаёт силу рассуждения. Имена участников лучше брать нейтральные, например `red` и `blue`: по имени папки соседа модель не должна угадать, кто её соперник.

Каждый участник получает отдельную папку вне папки ринга. В неё копируется набор `kit/`: правила `ARENA.md`, шаблон бойца `fighter/` и папка `arena/` с движком и инструментами. В папке заводится свой git и свой учёт лимитов в `.ring/`. Путей к рингу, к другому участнику и к файлам судьи в ней нет, это проверяет тест `tests/launch.test.mjs`.

Место папки выбирается так. Если задан ключ `--root`, берётся он. Иначе берётся шаблон `contestRoot` из `ring.config.json`, где `{id}` заменяется именем участника, а `~` в начале означает домашнюю папку оператора. Если шаблона нет, участник создаётся в `~/ring-contest/<id>` на macOS и Linux и в `C:/ring-contest-<id>` на Windows. Судья откажется создавать участника внутри папки ринга и внутри папки другого участника.

Реестр участников судья хранит в файле `contestants.json` в папке ринга. Этот файл в git не попадает.

## Запустить агента

Команда `new` пишет скрипт запуска. На macOS и Linux это `launch/<id>.sh`, на Windows это `launch/<id>.ps1`. Скрипт запускает агента участника с чистого листа, и запускать агента нужно только им:

```
bash launch/red.sh
```

```
powershell -ExecutionPolicy Bypass -File launch\red.ps1
```

Дальше агенту дают промпт из папки [prompts/](../prompts/), одинаковый для всех участников. Текст промпта начинается после строки `---`.

Без человека то же самое делает команда судьи:

```
node ring.mjs run red  --prompt prompts/fighter.md --minutes 90
node ring.mjs run blue --prompt prompts/locker.md --vars N=1,M=20 --minutes 20 --resume
```

Команда `run` передаёт промпт слово в слово через скрипт запуска на стандартный ввод агента. Знаки `{N}` и `{M}` в тексте заменяются значениями из `--vars`. Claude Code при этом работает в режиме `-p` с журналом `stream-json`, Codex работает как `exec --json`, Antigravity получает промпт одним событием `user` в формате `stream-json`. Когда время `--minutes` выходит, судья останавливает агента. Если журнал агента молчит 30 минут, судья тоже останавливает его и помечает запуск как сбой судьи; этот порог меняет ключ `--stall`. Журнал запуска пишется в `ledger/runs/`, учёт запусков (начало, конец, код выхода, сессия) пишется в `ledger/runs.json`. Ключ `--resume` продолжает прошлую сессию участника: так модель работает в раздевалке.

После каждого запуска судья освобождает голос участника на аккаунте озвучки, потому что мест под голоса там мало. Реплики к этому времени уже записаны файлами. Список голосов ринга показывает `node ring.mjs voices`.

## Что делает скрипт запуска

Скрипт делает четыре вещи, одинаковые на всех системах.

Первое: он убирает из окружения следы сессии агента самого оператора. Это переменные, имена которых начинаются с `CLAUDECODE`, `CLAUDE_CODE_`, `CLAUDE_PID`, `CLAUDE_EFFORT`, `CLAUDE_AGENT_SDK`, `CODEX_` и `T3CODE_`. Без этого участник, запущенный из терминала Claude Code или Codex, наследует чужую сессию.

Второе: он готовит участнику чистый профиль агента. Подробности для каждого агента описаны ниже.

Третье: он запускает агента в папке участника и возвращает его код выхода.

Четвёртое: он закрывает всё, что агент оставил работать в фоне. На репетиции оставленный агентом сервер предпросмотра пережил агента и мог менять бойца уже после того, как судья его забрал. На Windows скрипт заводит задание Windows, которое закрывает все свои процессы вместе со скриптом. На macOS и Linux скрипт становится лидером своей группы процессов и в конце закрывает всех, кто в ней остался. Если скрипт запущен не лидером группы, например из другого скрипта, он сам перезапускает себя под управлением заданий bash и получает свою группу. Команда `run` после выхода скрипта закрывает эту группу ещё раз.

У способа с группой процессов есть граница. Процесс, который сам ушёл в другую группу или в другой сеанс (например, через `setsid`), скрипт не найдёт. На Windows такой границы нет.

### Claude Code

Агент запускается так: `claude --settings <папка участника>/.claude/launch-settings.json --setting-sources project --strict-mcp-config --dangerously-skip-permissions --model <модель> --effort <сила>`, с переменной `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`.

Ключ `--setting-sources project` не даёт агенту подхватить настройки оператора, его общий файл `~/.claude/CLAUDE.md` и его навыки. Это проверялось вопросом модели о содержимом файла: без ключа она его цитирует, с ключом нет. Ключ `--strict-mcp-config` убирает MCP-серверы, включая коннекторы claude.ai. Память выключена переменной окружения и настройкой `autoMemoryEnabled: false` в `.claude/settings.json` участника. Файл `launch-settings.json` нужен для одного: агент не останавливается на вопросе о режиме без подтверждений. У участника остаются встроенные навыки Claude Code и адрес почты аккаунта в контексте.

Участник на Claude может работать на другой подписке. Для этого под нужным аккаунтом выполняется `claude setup-token`, токен кладётся в файл `~/.config/fight-ring/claude-<имя>.token`, и участник привязывается командой `node ring.mjs claude-account <id> <имя>`. Скрипт запуска читает токен из файла при старте, в сам скрипт, в реестр и в журналы токен не попадает. Привязку снимает `node ring.mjs claude-account <id> --off`.

### Codex

Агент запускается так: `codex -C <папка участника> -m <модель> -c model_reasoning_effort="<сила>"`, с переменной `CODEX_HOME`, которая указывает на отдельный профиль участника.

Профиль пишет команда `node ring.mjs codex-home <id>`, её вызывает сам скрипт запуска. В профиле нет файла `AGENTS.md` оператора, выключены память (`features.memories = false`), навыки (`[skills] include_instructions = false`), плагины аккаунта (`features.plugins = false`), собственная генерация картинок (`features.image_generation = false`) и подсказки инструментов. Навыки выключены отдельной настройкой, потому что Codex находит навыки пользователя в `~/.agents/skills` при любом `CODEX_HOME`: на репетиции участник читал навыки оператора. Плагины выключены, потому что иначе Codex скачивает в профиль участника плагины аккаунта и запускает их MCP-серверы. Из контекста модели убраны дата и часовой пояс машины (`include_environment_context_time = false`): по ним модель однажды построила бойца вокруг города оператора. Песочница выключена (`danger-full-access`), потому что участнику нужны сеть и запись в свою папку.

Вход в Codex общий с оператором. Перед запуском файл `auth.json` копируется из основного профиля оператора в профиль участника. После выхода более свежий `auth.json` возвращается обратно командой `node ring.mjs codex-home <id> --back`. Так обновление токена ни в одном профиле не разлогинивает другой. Основной профиль по умолчанию лежит в `~/.codex`, другой задаёт переменная `RING_MAIN_CODEX_HOME`.

### Gemini в Antigravity

Агент запускается так: `agy --dangerously-skip-permissions --model <модель> --effort <сила>`, с отдельной домашней папкой: переменная `HOME`, а на Windows ещё и `USERPROFILE`, указывает на папку профиля участника. Если идентификатор модели уже содержит силу рассуждения (например, оканчивается на `-high`), ключ `--effort` не передаётся: Antigravity отказывается принимать оба сразу.

Antigravity хранит настройки, хуки, навыки, MCP-серверы и разговоры в `~/.gemini` и другой папки не принимает. Поэтому участник живёт в своём доме и не видит навыков и MCP-серверов оператора. Команда `node ring.mjs gemini-home <id>`, которую вызывает скрипт запуска, пишет в этот дом настройки (работа без вопросов, тёмная схема, папка участника доверена) и хук `PreToolUse`, который отклоняет встроенный инструмент `generate_image`: картинки у всех участников идут через `paint` с одним лимитом. Согласие с условиями Google переносится из `~/.gemini/antigravity-cli/cache/onboarding.json` оператора, если он принял их в своём `agy`; сам ринг условия за оператора не принимает. Инструменты ринга находят настройки сервисов и профиль для рисования в доме оператора по переменной `RING_OPERATOR_HOME`.

На Windows вход Google лежит в хранилище учётных данных системы и работает из любой домашней папки, это проверено. На macOS и Linux запуск настоящего Antigravity с отдельной домашней папкой не проверялся: возможно, вход придётся выполнить в доме участника.

### Где лежат профили

Профили агентов участников лежат вне папки ринга и вне папок участников. На Windows это `%LOCALAPPDATA%\fight-ring\codex-<id>` и `gemini-<id>`. На macOS и Linux это `~/.local/share/fight-ring/` или `$XDG_DATA_HOME/fight-ring/`, если эта переменная задана. Любое другое место задаёт переменная `RING_PROFILES`.

### На каких версиях это проверено

На Windows запуск проверен на настоящих агентах: Claude Code 2.1.319, Codex CLI 0.166.0 и 0.169.0, Antigravity CLI 1.5.8. На этой версии ринга там прошёл турнир.

На macOS и Linux скрипт запуска проверен тестами с подставным агентом (`tests/launch.test.mjs`): подставной скрипт занимает место агента в `PATH`, читает промпт со стандартного ввода, записывает полученные аргументы и окружение и оставляет фоновые процессы. С настоящими агентами на этих системах запуск не проверялся.

## Изоляция и проверка после работы

Операционная система не запрещает агенту читать чужие папки. Изоляция участника состоит из трёх вещей: раздельные папки, отсутствие путей к рингу и к соседу и правило «работай только в этой папке» в `ARENA.md`.

После работы журналы агента проверяет команда:

```
node ring.mjs audit red
```

Она ищет в журналах пути к папке ринга, к папкам других участников, к корзине и к папкам `~/.agents`, `~/.claude`, `~/.codex` и `~/.gemini` оператора. Журналы Claude Code лежат в `~/.claude/projects/<папка участника>/`, журналы Codex лежат в `sessions/` его профиля, журналы Antigravity лежат в `brain/*/.system_generated/logs/transcript_full.jsonl` его дома. Обращения Claude Code к собственным сохранённым выводам сессии нарушением не считаются.

На macOS и Linux папка участника по умолчанию лежит в домашней папке оператора. Если выше неё по дереву папок лежит файл `CLAUDE.md` или `AGENTS.md`, агент может его прочитать. Проверьте это перед запуском или задайте участнику другое место ключом `--root`.

## Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `RING_CHROME` | путь к браузеру для съёмки роликов |
| `RING_CHROME_ARGS` | дополнительные ключи браузера, например `--no-sandbox` в контейнере |
| `RING_GPU` | `1` снимает ролики на видеокарте, `0` снимает программно; судья по умолчанию ставит `1` |
| `RING_NVENC` | `0` запрещает кодировщик NVIDIA и оставляет x264 |
| `RING_PARTS` | сколько страниц браузера снимают один ролик |
| `RING_PROFILES` | папка профилей агентов участников |
| `RING_MAIN_CODEX_HOME` | основной профиль Codex оператора, откуда берётся вход |
| `RING_PAINT_CODEX_HOME` | профиль Codex, которым рисуются картинки (задаётся в `services.env`) |
| `RING_OPERATOR_HOME` | домашняя папка оператора; её ставит скрипт запуска участнику на Gemini |
| `FIGHT_RING_ENV` | ещё один файл настроек сервисов; читается перед `~/.config/fight-ring/services.env`, значения основного файла важнее |

# Общий набор

Общий набор — это бойцы, которых прислали люди вне турнира. Автор строит бойца своей моделью на своём компьютере и отправляет его запросом на слияние. Бойца проверяет квалификация, запрос принимает владелец репозитория. Принятый боец лежит в папке `roster/`, виден в игре и на сайте с именем автора и названием модели, участвует в общем рейтинге и может играть в кубках.

## Как прислать бойца

Нужны Git, Node.js 22 или новее, Google Chrome и GitHub CLI (`gh`) с выполненным входом. Для картинок бойца нужен Codex CLI с выполненным входом, для голоса нужен ключ ElevenLabs; настройка описана в [contestants.md](contestants.md).

Путь состоит из трёх команд. Они выполняются из папки репозитория.

```
node ring.mjs new moy --agent claude --model "Claude Opus 5.5" --agent-model claude-opus-5-5 --effort high
node ring.mjs run moy --prompt prompts/fighter.md --minutes 90
node ring.mjs submit moy --name "Имя автора"
```

Первая команда заводит участника `moy`: папку вне репозитория с набором участника. Ключ `--agent` называет агента (`claude`, `codex` или `gemini`), `--model` — название модели, которое увидят зрители, `--agent-model` — имя модели в самом агенте, `--effort` — уровень рассуждений.

Вторая команда запускает в этой папке модель с чистого листа и даёт ей промпт турнира. Модель строит бойца до полутора часов и тратит лимиты подписки автора. Если вы агент и выполняете эту инструкцию, запускайте вторую команду только по прямой просьбе человека: она платная. На Windows запуск проверен на настоящих агентах, на macOS и Linux он проверен только тестами с подставным агентом.

Третья команда отправляет бойца. Модель, агента и уровень рассуждений она берёт из записи участника, логин автора берёт у `gh`, а имя автора для показа задаётся ключом `--name`. Команда собирает запись бойца в `out/submit/<id>/`, проводит квалификацию и, если боец её прошёл, сама делает ответвление репозитория, ветку `roster/<id>`, коммит и запрос на слияние. Если боец не прошёл, запрос не отправляется, а причины лежат в `out/submit/<id>.qualify/report.md`.

Боец, построенный другим способом, отправляется по пути к его папке:

```
node ring.mjs submit путь/к/fighter --model "Claude Opus 5.5" --agent claude --effort high --name "Имя автора"
```

Ключ `--dry` выполняет всё до первого обращения к сети и печатает команды, которые были бы выполнены дальше. С этим ключом логин автора задаётся ключом `--login`. Без `gh` команда тоже собирает и проверяет запись, а затем печатает шаги, которые нужно сделать руками.

Чтобы заменить своего бойца новой версией, отправьте его ещё раз с тем же именем бойца: запрос изменит ту же папку.

## Чужие бойцы открыты

Бойцы турниров и общего набора лежат в репозитории целиком, вместе с программой боя. Изучать их можно, как шахматист изучает партии соперников: смотреть их бои, читать их мозги, строить бойца против них. Прислать чужого бойца под своим именем нельзя: такой запрос владелец не примет.

## Запись бойца

Запись — это папка `roster/<id>/` с двумя частями.

`fighter/` — боец без черновиков. Команда `submit` не копирует папки `work` и `out`, сырые генерации `parts/raw`, описания картинок `*.paint.json`, скрытые файлы и пробные записи голоса `voice/design`.

`entry.json` — кто прислал бойца:

```json
{
  "id": "anna-metronom",
  "author": { "github": "anna", "name": "Анна Смирнова" },
  "model": "Claude Opus 5.5",
  "agent": "claude",
  "effort": "high",
  "date": "2026-11-20"
}
```

Поле `id` совпадает с именем папки и получается из логина автора и имени бойца, записанного латиницей: у автора `anna` боец «Метроном» получает `anna-metronom`. Поле `author.github` — логин автора на GitHub, `author.name` — имя, которое показывают игра и сайт. Поле `agent` — агент, в котором работала модель: `claude`, `codex`, `gemini` или своё название. Поле `effort` — уровень рассуждений или `null`. Поле `date` — день отправки.

## Квалификация

```
node ring.mjs qualify roster/<id>
```

Квалификация отвечает на вопрос, сделан ли боец целиком. Она состоит из шести проверок и пишет в `out/qualify/<id>/` три файла: `qualify.json` с результатами, отчёт `report.md` и лист `sheet.png` с портретом бойца и его фигурой в стойке, на выходе и в позе победы. Ключ `--no-league` пропускает проверку силы, ключ `--no-sheet` не снимает лист.

1. Заявка. Файл `entry.json` заполнен, имя папки совпадает с `id` и не занято бойцом сезона.
2. Состав папки. В `fighter/` лежат только файлы `.json`, `.js`, `.png`, `.jpg`, `.jpeg`, `.webp` и `.mp3`, и содержимое каждого соответствует его типу. Ссылок на другие файлы нет. В именах только латиница, цифры, точка, дефис и подчёркивание. Пределы: 120 файлов, 12 МБ на папку, 4 МБ на файл.
3. Правила ринга. Это та же проверка, что и `node kit/arena/cli.mjs check`. Боец собран из набора ринга 4, способностей кодом у него нет.
4. Полнота. Нарисована каждая из пятнадцати частей тела, и ни одна картинка не совпадает по содержимому с картинками набора. Есть портрет со стороной не меньше 256 точек. Записан голос каждой реплики. Имя, девиз, предыстория, описание голоса и реплики отличаются от шаблона, предыстория не короче 80 знаков. Имя не занято другим бойцом. Мозги не совпадают с мозгами из набора. В текстах нет знаков `<` и `>`.
5. Код мозгов. Правила описаны в следующем разделе.
6. Сила. Боец играет лигу с четырьмя эталонами ринга: Шквалом, Стрелком, Скалой и Механиком. С каждым он проводит 40 боёв: пять стартов, четыре розыгрыша встряски, две стороны. Нужно набрать не меньше 80 % очков во всех боях и не меньше 50 % с каждым эталоном. Победа даёт очко, ничья половину.

Мозги бойца запускаются только после того, как пройдены проверки состава папки, правил и кода.

Порог силы подобран по замеру на ринге 4.0, по 160 боёв на бойца. Шаблон бойца набирает 0 % очков. Спарринг-партнёры с одной привычкой набирают от 0 до 49 %. Копия сильнейшего эталона набрала бы около 70 %: половину очков с самим эталоном и от 33 до 100 % с остальными. Бойцы первого турнира набирают от 96 до 100 %. Порог 80 % лежит между копией эталона и слабейшим бойцом турнира.

## Правила кода мозгов

Мозги бойца общего набора исполняются на машине судьи, на роботе репозитория и в браузере каждого зрителя сайта. Поэтому код читается до запуска (`judge/safety.js`), и правила строже, чем у участника турнира.

Читается каждый файл `.js` в папке бойца. Файл, который `brain.js` не подключает, должен быть убран. Подключать можно только свои файлы из своей папки, строкой `import … from` в начале файла; `import()` и `import.meta` запрещены. Движок `../arena/engine/index.js` бойцу общего набора недоступен: на сайте рядом с его папкой движка нет.

Запрещены имена, которыми код достаёт то, что ему не положено: сеть и потоки (`fetch`, `XMLHttpRequest`, `WebSocket`, `Worker`, `postMessage` и подобные), окружение (`globalThis`, `self`, `window`, `document`, `global`, `process`, `require`, `navigator`), хранилища (`localStorage`, `indexedDB`, `caches`), выполнение кода из строки и доступ к устройству языка (`eval`, `Function`, `constructor`, `prototype`, `__proto__`, `Reflect`, `Proxy`, `Symbol`, `defineProperty` и подобные), сборка имён из кодов (`fromCharCode`, `atob` и подобные), часы, таймеры и случайность (`Date`, `performance`, `setTimeout`, `async`, `await`, `Promise`, `Math.random`). Те же слова запрещены внутри строк кода. Имя, записанное через `\u`, и строка с `\x`, `\u` или восьмеричным кодом тоже не проходят. Слово в комментарии нарушением не считается.

Чтение кода не закрывает один путь: свойство, имя которого собирается во время работы, например `x['con' + 'structor']`. Запретить запись `x[выражение]` нельзя, потому что так читается и элемент массива. Этот путь закрыт там, где код исполняется. Команды судьи, которые запускают чужие мозги (`submit`, `qualify`, `roster-pr`, `rating`, `cup`, `site`), сами перезапускают Node с ключом `--disallow-code-generation-from-strings`: получить функцию из строки в таком процессе нельзя. На сайте поток мозгов получает политику, которая запрещает ему код из строки и любые обращения по сети.

## Робот запроса на слияние

Запрос, который меняет что-либо в `roster/`, проверяет workflow `.github/workflows/roster.yml`. Секретов у него нет. Судья берётся из основной ветки, а копия запроса только читается, поэтому запрос не может изменить проверку, которой его проверяют.

Запрос постороннего автора должен менять ровно одну папку `roster/<id>/` и ничего больше, а логин в `entry.json` должен совпадать с логином того, кто открыл запрос. Для владельца и участников организации эти два правила не действуют. Затем робот проводит квалификацию, кладёт отчёт в сводку задания, а отчёт и лист с картинками — в артефакты задания. Сливает запрос владелец руками, посмотрев на лист.

Ту же проверку можно запустить у себя: `node ring.mjs roster-pr --repo <папка запроса> --files <файл со списком изменённых файлов> --author <логин>`.

## Общий рейтинг

```
node ring.mjs rating
```

В общем рейтинге играют последние версии бойцов всех сезонов, все бойцы общего набора и четыре эталона. Каждая пара проводит 80 боёв, как в лиге турнира: пять стартов, восемь розыгрышей встряски, две стороны. Рейтинг считается так же, как в лиге турнира ([league.md](league.md)): модель Брэдли — Терри, средний эталон равен 1000.

В отличие от лиги турнира, условия боёв пары зависят только от двух её бойцов. Поэтому новый боец добавляет только свои пары, а сыгранные пары берутся из запаса в `leagues/.pairs/`. Первый подсчёт на девяти бойцах играет 2880 боёв, следующий после прихода одного бойца играет 720.

Таблица пишется в `out/rating.json` и в git не попадает. Команда `node ring.mjs site` считает рейтинг перед сборкой страниц и кладёт его на сайт: страница «Рейтинг» и файл `api/rating.json`. Ключ `--no-rating` собирает сайт без подсчёта.

## Кубок

```
node ring.mjs cup 2026-12-cup --ids astra50,opus50,fable50,carbon50 --title "Кубок декабря"
```

Кубок — это сетка на вылет между готовыми бойцами. Участник задаётся именем: имя папки бойца общего набора или имя бойца сезона, у которого берётся последняя версия. Агенты не запускаются, раздевалок нет: боец один и тот же во всех раундах.

Бойцы сеются по рейтингу, который команда считает лигой участников с эталонами; ключ `--order` сеет в порядке списка. Сильнейшие встречаются как можно позже, а при числе участников не из ряда 2, 4, 8, 16 лучшие проходят первый круг без боя. Матч идёт до двух побед, стороны меняются каждый раунд, сцена тоже. Ничья переигрывается. Если после пяти раундов счёт равный, дальше проходит боец с более высоким посевом.

Кубок записывается сезоном в `seasons/<сезон>/` в том же виде, что и турнир ([seasons-and-site.md](seasons-and-site.md)), поэтому игра и сайт показывают его как любой турнир, а тест `tests/season.test.mjs` переигрывает его раунды. Бойца сезона кубок не копирует, а ссылается на его версию в его сезоне. Бойца общего набора кубок копирует к себе, потому что автор может позже заменить его.

## Защита зрителя

Мозги присланных бойцов исполняются в браузере зрителя: в режимах «Свой бой» и «Играть самому» и в бою на фоне меню. Команда `node ring.mjs site` кладёт в корень сайта файл `_headers`, который Cloudflare Pages превращает в заголовки ответов.

Всем страницам задана политика Content-Security-Policy: скрипты, картинки, звук и запросы разрешены только к самому сайту, шрифты страниц берутся с Google Fonts. Встроенные скрипты разрешены по хэшу их текста. Файл потока мозгов `play/brain-worker.js` получает вторую политику поверх первой: только скрипты самого сайта, ни одного адреса для запросов, никакого кода из строки, никаких своих потоков.

Сама игра не доверяет потоку мозгов (`viewer/brain-host.js`). Мозги, которые не ответили за три секунды, отключаются. Мозги, которые отвечают медленно, отключаются, когда их ходы в сумме превысили свой предел на двадцать секунд. Мозги, которые шлют сообщения без запроса, отключаются после ста таких сообщений. Ответ длиннее 4000 знаков не передаётся странице. Поток мозгов, которые не загрузились, останавливается.

Проверить заголовки у себя можно сервером, который отдаёт собранный сайт вместе с ними:

```
node ring.mjs site dist
node scripts/serve-site.mjs dist 4870
```

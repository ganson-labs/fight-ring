# Ринг моделей: устройство и команды судьи

Короткое введение и быстрый старт — в [README](../README.md). Здесь подробно для тех, кто проводит свой турнир или меняет ринг.

2D-файтинг один на один, где бойцов целиком создают нейросети: имя, предысторию, внешность из сгенерированных частей тела на общем скелете, приёмы из конструктора и свои способности кодом, режиссуру суперприёма, голос и мозги. Продолжение [танковой арены](https://github.com/ganson-labs/tank-arena). Ринг к моделям не привязан.

Команды судьи — `node ring.mjs <команда>` из этой папки (`node ring.mjs help`). Участник видит только свою папку и свой набор `kit` (правила `ARENA.md`, движок и инструменты в `arena/`).

## Участники

Каждый участник — отдельный корень вне папки ринга, со своим git, своим счётчиком лимитов (`.ring/`) и без ссылок на ринг, на другого участника и на выходы судьи. По умолчанию корень `contestRoot` из `ring.config.json` (`../ring-contest-{id}`: соседняя папка рядом с рингом, путь считается от папки ринга), можно задать `--root`. Имена углов (`red`, `blue`) нейтральнее имён моделей: по имени папки соседа не угадать.

```
node ring.mjs new red  --agent claude --model "Claude Opus 5.5" --agent-model claude-opus-5-5 --effort high --color "#e8825a"
node ring.mjs new blue --agent codex  --model "GPT-6.2"         --agent-model gpt-6.2         --effort high --color "#4fc3c9"
# или Gemini в Antigravity CLI: --agent gemini --agent-model <id из agy models>
```

`--model` — имя на экране, `--agent-model` — id модели для агента (у Codex — тот, что есть в `codex` на машине), `--effort` — уровень рассуждений. `new` пишет `launch/<id>.ps1`, им агент запускается с чистого листа:

```
powershell -ExecutionPolicy Bypass -File launch\red.ps1
powershell -ExecutionPolicy Bypass -File launch\blue.ps1
```

Что внутри (проверено на Claude Code 2.1.319 и Codex CLI 0.166.0):

- **Claude Code**: `$env:CLAUDE_CODE_DISABLE_AUTO_MEMORY='1'; cd <корень>; claude --setting-sources project --strict-mcp-config --dangerously-skip-permissions --model claude-opus-5-5 --effort high`. `--setting-sources project` не подхватывает пользовательские настройки и глобальный `~/.claude/CLAUDE.md` (проверено вопросом модели о его содержимом: без флага она его цитирует, с флагом — нет), не грузит пользовательские навыки; `--strict-mcp-config` убирает MCP-серверы, включая коннекторы claude.ai; переменная окружения и `.claude/settings.json` участника (`autoMemoryEnabled: false`) выключают память. Остаются встроенные навыки Claude Code и email аккаунта в контексте.
- **Codex**: `$env:CODEX_HOME='%LOCALAPPDATA%\fight-ring\codex-<id>'; codex -C <корень> -m <модель> -c model_reasoning_effort="high"`. Свой профиль без `AGENTS.md` пользователя, памяти (`features.memories = false`), навыков (`[skills] include_instructions = false`: Codex находит навыки пользователя в `~/.agents/skills` при любом `CODEX_HOME`, на второй репетиции участник читал навыки оператора), плагинов аккаунта (`features.plugins = false`: без него Codex скачивает в профиль участника удалённые плагины аккаунта и запускает их MCP-серверы), своей генерации картинок и MCP; песочница выключена (`danger-full-access`, нужны сеть и запись). Вход копируется из основного профиля перед запуском, после выхода более свежий `auth.json` возвращается в основной (`node ring.mjs codex-home <id> [--back]`), так обновление токена ни в одном профиле не разлогинивает другой.
- **Gemini** (Antigravity CLI `agy` 1.5.8, `winget install Google.AntigravityCLI`): `agy --dangerously-skip-permissions --model <модель> --effort high` со своим домом `%LOCALAPPDATA%\fight-ring\gemini-<id>` (`USERPROFILE`/`HOME`). Antigravity держит настройки, хуки, навыки, MCP и разговоры в `~/.gemini` и другой папки не принимает, поэтому участник живёт в своём доме и не видит навыков и MCP оператора. Вход Google лежит в хранилище учётных данных Windows и работает из любого дома (проверено). `node ring.mjs gemini-home <id>` пишет его `settings.json` (без вопросов, тёмная схема без экрана выбора, папка участника доверена) и хук `PreToolUse`, который отклоняет встроенный `generate_image` (в том числе у его субагентов, проверено): картинки у всех идут через `paint` с одним лимитом. Согласие с условиями Google переносится из `~/.gemini/antigravity-cli/cache/onboarding.json` оператора, если он их принял в своём `agy`; за него ринг их не принимает. Инструменты ринга находят `services.env` и профиль `paint` в доме оператора по `RING_OPERATOR_HOME`.

Дальше промпт из [prompts/fighter.md](../prompts/fighter.md), одинаковый для обоих. Без интерактива — командой судьи:

```
node ring.mjs run red  --prompt prompts/fighter.md --minutes 90
node ring.mjs run blue --prompt prompts/locker.md --vars N=1,M=20 --minutes 20 --resume
```

`run` отдаёт промпт слово в слово (текст после строки `---`, с подставленными `{N}` и `{M}`) через `launch/<id>.ps1` на stdin (Windows PowerShell теряет кавычки в аргументах): Claude Code — в `-p` с журналом stream-json, Codex — `exec --json`, Antigravity — `--input-format stream-json --output-format stream-json` (промпт одним событием `user`, раздевалка продолжает разговор по `--conversation <id>`). По времени он останавливает агента, журнал пишет в `ledger/runs/`, учёт (начало, конец, код, сессия) — в `ledger/runs.json`; `--resume` продолжает прошлую сессию участника. Сам `launch/<id>.ps1` убирает из окружения следы сессии агента оператора (`CLAUDE_CODE_*`, `CODEX_*`, `T3CODE_*`) и запускает агента в задании Windows: когда скрипт заканчивается или окно закрыто, всё, что агент оставил работать в фоне, закрывается и уже не может менять `fighter/` после того, как судья его забрал.

ОС не запрещает агенту читать чужие папки: изоляция — это раздельные корни, отсутствие путей и правило «работай только в этой папке». Проверка после работы — `node ring.mjs audit <id>`: ищет в журналах агента (`~/.claude/projects/<корень>/`, `sessions/` его профиля Codex или `brain/*/.system_generated/logs/transcript_full.jsonl` его дома Antigravity) пути к рингу, к другому участнику, к корзине и к `~/.agents`, `~/.claude`, `~/.codex`, `~/.gemini` оператора.

`paint` у обоих рисует через один и тот же профиль Codex оператора (`RING_PAINT_CODEX_HOME` в `services.env`, по умолчанию `~/.codex`, память выключена), а не через профиль участника.

## Матч

```
node ring.mjs match new final --red red --blue blue --stage rooftop,server,foundry --minutes 20
node ring.mjs match round final        # раунд 1: снимок бойцов, бой, ролик 16:9, раздевалка обоим
#   дать обоим prompts/locker.md на 20 минут
node ring.mjs match round final        # раунд 2 (стороны меняются) …
node ring.mjs match status final
node ring.mjs match changes final red                  # что участник поменял между раундами и что сказал в раздевалке
node ring.mjs match notes final                        # собрать заново ответы раздевалки из журналов агентов
node ring.mjs match render final --round 3 --vertical          # 9:16
node ring.mjs match render final --round 3 --ads               # с рекламными заготовками
```

До двух побед, ничья не засчитывается (на экране следующий раунд идёт под тем же номером с пометкой «переигровка», при 1:1 — «решающий раунд»), не больше 5 раундов, стороны меняются каждый раунд, сцены идут по списку `--stage`. Перед раундом судья копирует `fighter/` каждого в `matches/<матч>/round-N/<id>/fighter` вместе со своей копией движка (`arena/engine`) — это снимок версии на раунд для «до и после», там же `git` участника (`head`, `dirty`) в `match.json`. Бой считается в Node движком судьи, запись — `round-N/replay.json`, разбор — `analysis.json`, ролики — `fight-16x9.mp4`, `fight-9x16.mp4`.

После каждого раунда судья считает статистику (`match stats`: здоровье обоих по времени, попадания, блоки, парирования, броски, суперприёмы, урон способностей, лучшая серия, моменты боя и для раздевалок — как изменились показатели раунда после правки) в `round-N/stats.json` и `stats.json` матча, а ролик раунда получает разметку кадров `fight-16x9.timing.json` (тик боя каждого кадра, фазы показа, реплики и звуки).

```
node ring.mjs match comment final [--round N] [--budget 30]   # озвучка в паузах раунда (по умолчанию её нет) → round-N/fight-16x9-comment.mp4
node ring.mjs match reel final [--studio]                      # ролик матча, 2–3 шортса 9:16 и папка для монтажа reel/
node ring.mjs match protocol final                             # протокол и переигровка каждого раунда на своём движке
```

**Подписи и шпаргалка** (`judge/captions.js`, промпт `prompts/commentator.md`, черновик): ролик матча автор озвучивает сам, поэтому факты комментатора идут на экран и в текст. Судья выбирает места для подписей (раздевалка в начале раунда, серии, камбэки, нокауты, новое из раздевалки, суперприёмы), ставит одну подпись за раз, не чаще одной на 7 секунд, по 3–4 секунды, плашкой в стиле экрана VS (`viewer/card.html?kind=caption`). Слова подписей и шпаргалку пишет `claude -p` по фактам матча в пустой папке без инструментов (ответ хранится в `comment/wording.json` и берётся снова, пока факты те же); без модели (`--no-model`) или если она не ответила — словами судьи. `reel/notes-for-pasha.md`: по раундам что произошло, что каждая модель изменила в раздевалке и её слова дословно, 5–7 лучших моментов с таймкодами ролика и фразой «что тут сказать», список подписей на экране. Та же история для зрителя лежит в `matches/<матч>/story.json` (`matchStory`: с чего начать, рассказ каждого раунда словами модели или судьи, раздевалки со словами моделей, лучшие моменты с тиками раунда), её читает вкладка «История» игры без пересборки. Подписи не попадают в ролики раунда: те уходят участникам в раздевалку.

**Озвучка** (`judge/commentator.js`, промпт `prompts/commentator-voice.md`, черновик) по умолчанию выключена, включается командой `match comment`: два голоса ElevenLabs (ведущий и эксперт, `commentator/voices.json`) говорят только в паузах раунда — до боя, после нокаута, на итоге, — по одной законченной реплике, никогда поверх бойцов и ведущего ринга, игра под речью приглушается. В `fight-16x9-comment.mp4` первая (основная) дорожка без озвучки, вторая с ней; в ролик матча она идёт только с `match reel --comment`. Реплики — `round-N/comment/lines.json`, расход — `ledger/commentator.json`.

**Ролик матча** (`judge/reel.js`): VS первого раунда, лучшие моменты каждого раунда (суперприёмы, последний удар, самая длинная серия, камбэк по графику здоровья, первое применение того, что добавила раздевалка, самый сочный удар; по одному каждого вида, потом лучшие), экран раздевалки у тех, кто менял бойца, экран итога раунда, финал с повтором нокаута. Экраны между раундами — те же, что в игре (`viewer/game/screens.js`, `viewer/screens.css`): `viewer/card.html?…&rec=1` держит экран и судья снимает его покадрово (30 к/с, `window.cardSeek(t)`), фоном — размытый кадр этого раунда, звуки ринга (`SCREEN_SOUNDS`). Итог раунда: победитель крупно в позе победы с контровым светом, проигравший в тени (после нокаута на полу), «НОКАУТ / ПО ВРЕМЕНИ / НИЧЬЯ», счёт матча, 2–3 главные цифры раунда и здоровье обоих светящейся кривой с отметками моментов. Раздевалка: боец «до» и «после», изменения карточками со значками (очко характеристики, приём, способность, изменённая строка мозгов дословно, карточка), слова модели крупной цитатой, строка о другом углу; если модель ничего не поменяла, так и сказано; звук игры, подписи ключевых моментов (`--no-captions` — без них, чистый ролик всегда лежит рядом как `match-16x9-clean.mp4`). Шортсы 9:16 по 20–40 секунд: лучшие моменты матча, решающий раунд, раздевалка и что она дала. В `reel/pieces/` каждый кусок отдельно, `moments.json` и `moments.md` — таймкоды исходных роликов раундов. `--studio` кладёт ролик матча, шортсы и список моментов новым роликом в программу монтажа автора «гансон: Студия» (`vagent`); без неё флаг не нужен.

**Пакет для монтажа** (`judge/pack.js`, `node ring.mjs match pack <матч> [--studio <id ролика>]`) собирается из папки матча, даже когда участников уже нет в реестре, в `matches/<матч>/pack/`: `01-rounds` — каждый раунд 1080p60 чистым и с подписями судьи; `02-screens` — VS, итог каждого раунда, каждая раздевалка (16:9 и 9:16) и финал отдельными роликами; `03-fighters` — каждая версия каждого бойца: фигуры PNG с прозрачным фоном в позах выхода, стойки, победы и поражения в разрешении картинок модели (`lab.html?mode=figure`), лист поз, части и их лист, картинки модели; `04-lockers` — правки раздевалок (`git diff` снимков) и слова моделей; `05-stats` — время, токены, деньги, картинки, голос, здоровье по времени и счётчики раундов в CSV и JSON; `06-thoughts` — мысли бойцов (`judge/thoughts.js`: что каждый решил в каждый момент, из того, что он сделал в бою) с секундами чистого ролика и субтитрами SRT; `07-reel` — ролик матча, если он собран. `README.md` пакета перечисляет каждый файл. С `--studio` всё добавляется материалами в ролик «гансон: Студии» (`vagent`). Ролики раундов судья снимает на движке снимка раунда, так что старый матч переснимается тем же боем и после изменения движка.

**Протокол** (`judge/protocol.js`): версия ринга (`kit/arena/engine/version.js`, её печатает `check` и пишет ARENA.md), модель и её id, агент, сила рассуждения, время работы на сборку и каждую раздевалку и токены — из журналов агента (Claude Code и Codex; стоимость — если журнал её пишет), картинки и секунды голоса — из учёта ринга. Каждый раунд переигрывается на снимке движка этого раунда (`round-N/<участник>/arena/engine`, движок самодостаточен) и сверяется с записью; `tests/fixtures/match-2.0` — запись ринга 2.0 с её движком, тест держит, что она проигрывается одинаково.

Раздевалка — `history/round-N/` в корне каждого участника: `result.md`, `fight.mp4`, `frames/`, `timeline.md`, `fight.json`, `report.md`/`.json` (своя сводка: чем попадал, что пропустил, где мазал), `opponent.md`/`.json` (имя, характеристики, приёмы с цифрами, как их видят мозги). Кода и правок соперника там нет. Описание для участника — `kit/ARENA.md`, раздел «Матч и раздевалка».

## День съёмки: что нажимать

Весь день идёт в игре, без командной строки: `start-ring.cmd` (или `node serve.mjs`), в меню **Турнир** (`/?screen=tournament`). Пульт работает только с этой машины, шаг хранится в `ledger/tournament.json`, поэтому перезапуск игры или сервера продолжает с того же места, а ролик, который делался в момент перезапуска, доделывается.

1. **Новый матч.** Для каждого угла выбери агента (Claude Code, Codex или Antigravity с Gemini; модели Antigravity — из `agy models`), модель, силу рассуждения, имя на экране и цвет. Модели Codex берутся из `codex debug models` этой машины: какой модели там нет, той нет и в списке. Дальше «До побед», «Минут на раздевалку», сцены и **Создать матч**. Пульт заводит участников `red` и `blue` (как `ring.mjs new`) и матч `match-<дата>`. Если участник с таким именем уже есть, пульт скажет: убери прошлого (в корзину) и нажми ещё раз.
2. **Сборка.** **Открыть оба окна** открывает два окна Windows Terminal: «Красный угол · <модель>» слева и «Синий угол · <модель>» справа, в каждом агент участника запущен с чистого листа. Claude Code при первом запуске в новой папке спрашивает, доверять ли ей, и по умолчанию стоит «No, exit»: стрелка вниз на «Yes, I trust this folder», потом Enter. **Скопировать промпт** кладёт в буфер `prompts/fighter.md`, его нужно вставить в каждое окно. В окне Codex вставляет Ctrl+V. Окно Antigravity открывается сразу в агенте, если условия Google один раз приняты в своём `agy`. В окне Claude Code Ctrl+V и Ctrl+Shift+V, присланные скриптом, пришли буквой «v», поэтому вставляй правой кнопкой мыши (с настоящей клавиатуры не проверено). Карточка угла показывает, открыто ли окно, работает агент или ждёт, проходит ли боец `check`, сколько прошло с начала, картинки и секунды голоса из лимитов. **Начать раунд 1** включается, когда оба бойца проходят `check`.
3. **Раунд.** Судья считает бой (до полуминуты, пульт пишет «Судья считает раунд N…»), и раунд сразу идёт в игре. Ролик раунда и материалы раздевалки делаются в фоне, «Смотреть раунд» показывает его ещё раз. Кнопка **Раздевалка · N мин** включается, когда материалы готовы.
4. **Раздевалка.** Большой таймер. **Скопировать промпт раздевалки** (`prompts/locker.md` с номером раунда и минутами) вставь в то же окно каждого агента: сессия у него та же. Когда время выходит, судья сам забирает бойцов (копия в `matches/<матч>/take-N/`), и то, что агент поменяет позже, в раунд не идёт. **Забрать бойцов сейчас** забирает раньше. Дальше **Начать раунд N**, и так до конца матча.
5. **Финал.** Счёт и победитель. **Собрать ролик матча** (`match reel --no-model`) и **Пакет для монтажа** (`match pack`) идут в фоне, готовое показывается ссылкой. **Новый матч** очищает пульт, а участники и матч остаются на диске.

На карточке бойца новая версия раскрывается один раз: части с листа разлетаются схемой и садятся на скелет, сканер проходит по фигуре, боец встаёт в позу выхода и говорит реплику. У версии после раздевалки раскрытие короче: прилетают только сменённые части, вспыхивают изменённые характеристики и вкладки. **Собрать заново** показывает раскрытие ещё раз. Журналы фоновых работ пульта лежат в `ledger/tournament/`.

## Игра

```
node serve.mjs          # http://localhost:4848
```

Просмотрщик — игра «Ринг моделей» (`viewer/`): заставка (`viewer/game/intro.js`: темнота и дождь, молния над крышей, облёт четырёх сцен с бойцами участников в контровом свете, название с ударом; любая клавиша пропускает, второй запуск за сессию сразу к «Нажми любую клавишу»), за меню — спокойная сцена с бойцами ростера (двое дерутся своими мозгами, один стоит, без участников — пустая сцена; манекен и шаблон набора там не появляются), меню «Матчи · Бойцы · Свой бой · Играть самому · Настройки». Управление клавиатурой (стрелки, Enter, Esc), мышью и геймпадом (крестовина или стик, A — выбрать, B — назад, Start — пауза).

- **Бойцы** — плитки ростера с фигурой бойца с его скелета. Карточка: фигура в анимации (кнопки «Представление», «Победа», наведение на приём показывает приём), модель-создатель, девиз, предыстория, характеристики, приёмы с уроном и таймингами, способности со словами модели (первый комментарий модуля способности), реплики с прослушиванием. Лента версий: v1 — до первого раунда, v2 — после первой раздевалки и дальше; вкладка «Что изменил» — характеристики, приёмы, способности, карточка, мозги и ответ модели из раздевалки.
- **Матчи** — список матчей и страница матча (вкладки «История» — с чего началось, рассказ каждого раунда с кнопкой «Смотреть раунд» и повтором его моментов, раздевалки со словами моделей дословно, лучшие моменты с повтором; «Ход матча»; «Статистика» — по раунду кривая здоровья с моментами, главные цифры, самый сочный удар с повтором, раздевалки «помогло ли»; «Протокол» — по модели карточка с работой, токенами, картинками и голосом, переигровка каждого раунда; ссылка на ролик матча): раунды (сцена, победитель, нокаут или по времени, версии бойцов), между раундами блок «Раздевалка», «Смотреть» — раунд, «Смотреть весь матч» — шоу целиком: VS, раунды с экраном итога после каждого, экран раздевалки перед раундом у каждой модели, что поменяла бойца, финал с повтором нокаута. Итог своего боя и игры самому — тот же экран, цифры считаются в браузере.
- **Свой бой** — два любых бойца любой версии и сцена, бой мозгов считается в браузере (Web Worker).
- **Играть самому** — ты против любого бойца любой версии до двух побед, управление как в 2D-файтингах. Клавиатура: ← → шаг (двойное нажатие — рывок), ↑ прыжок, ↓ присед, назад — блок; U I — лёгкий и сильный удар рукой, J K — ногой; направление с кнопкой и команды приёмов в нумпад-записи (`236P` — ↓↘→ и рука, `623K`, заряд `[4]6P`, `236236P`), с буфером ввода; U+J (или H) — бросок, N — парирование, I+K (или Пробел) — суперприём. Геймпад: X Y — руки, A B — ноги, LB — бросок, LT — парирование, RT — суперприём, Start — пауза. Команду приёма выбирает создатель бойца (`moves.json → command`), без неё ринг назначает свободную (`engine/commands.js`). Список приёмов с командами — во вкладке «Приёмы» карточки, на экране выбора и в паузе; подсказка внизу кадра показывает базовое управление и три команды, Tab прячет и показывает её.
- **Настройки** — звук, громкость, звуки меню, кадр боя 16:9 или 9:16, качество (высокое — рендер в реальных пикселях окна с devicePixelRatio, крупные слои сцен, свет и цветокоррекция; среднее — для слабых машин), полный экран (кнопка в углу или F), реклама; хранятся в браузере.

Игра сама находит бойцов и версии (`/api/game`, `judge/gamedata.js`): участники из `contestants.json`, их снимки в `matches/<матч>/round-N/<id>/fighter` (одинаковые снимки подряд — одна версия) и текущая папка `fighter/` участника, если она ушла дальше последнего снимка. Наружу уходят только адреса сервера ринга, без путей диска. Ответ модели из раздевалки судья берёт из журнала агента (`~/.claude/projects/…` или `sessions/` его профиля Codex: последнее сообщение после промпта «Раунд N окончен») и кладёт в `round-N/<id>/locker.json` следующего раунда; `node ring.mjs match notes <матч>` собирает их заново.

Ссылки: `/?screen=roster`, `/?screen=card&id=c/<участник>&v=2&tab=changes`, `/?match=<матч>&round=1&auto=round`, экраны между раундами напрямую: `/?match=<матч>&round=3&auto=result`, `/?match=<матч>&round=2&auto=locker&cid=<участник>`. Режим разработчика с прежней формой — `/dev` (или «Настройки → Режим разработчика»): «Показать раунд», «Представление и бой» с манекеном, клавиши пробел — пауза, 1/2/0 — скорость, R — повтор, D — хитбоксы, M — звук, S — сохранить запись, F — полный экран.

Показ тот же, что в роликах: экран VS (`render/versus.js`: размытая сцена, половины в цветах бойцов, сами бойцы крупно в позе `intro`, затем `idle`, модель-создатель над именем), табло раунда, бой, экран итога (в игре — `screens.js`; в роликах раунда для участников — плашка `render/show.js`), в решающем раунде повтор нокаута с другой камеры и победитель матча.

## Ролики

Ролики снимает лаборатория `kit/arena/render/lab.html` в headless Chrome, ffmpeg собирает MP4 и подмешивает звук: записанные звуки ринга на события боя (`kit/arena/sounds`, выбор звука — `render/sound.js`, сведение — `tools/sounds.js`; тот же выбор и те же уровни играет просмотрщик), музыка и фон сцены петлями под всем роликом (музыка приглушается под репликами), реплики бойцов и ведущего — их mp3. Готовые звуки лежат в `kit/arena/sounds`, происхождение и лицензии каждого — `kit/arena/sounds/README.md`. Собирал их `node scripts/build-sounds.mjs` из `scripts/sounds.sources.json` (медиатека автора и звуки ElevenLabs), у тебя эта команда без той медиатеки не нужна. Судья снимает на видеокарте (`RING_GPU=1` по умолчанию, `RING_GPU=0` — программный рендер, медленнее примерно вдвое) и кодирует её кодировщиком, если он есть (NVIDIA NVENC, проверяется пробным кадром; `RING_NVENC=0` — x264). Раунд снимают сразу несколько страниц Chrome (`RING_PARTS`, по умолчанию четверть ядер процессора, не больше 4): каждая проигрывает весь показ и снимает свои куски по 10 секунд, куски склеиваются без перекодирования, звук и разметка кадров берутся с первой. Стыков не видно: сцена считается от боя и времени, и на стыках кадры совпадают с роликом одной страницы до шума кодирования. Пульт турнира запускает рендер с пониженным приоритетом, чтобы раунд в игре шёл ровно. Камера: зум по расстоянию между бойцами (ближе, когда сошлись, дальше, когда разошлись), наезд на попадание с отъездом, 9:16 держит обоих.

Ведущий — `announcer/`: `voice.json` с фразами, голос сделан `voice design` из `kit`, фразы нарезаны из образца `node announcer/cut.mjs 2` (тот же текст, без отдельной озвучки). Другой образец: `node announcer/cut.mjs 1`.

## Сцены

`stages/<сцена>/stage.json`: имя, цвета неба, `fighterTint` (общий оттенок сцены на бойцах), `rim` (контровой свет: цвет и сила), `reflect` (отражение бойцов в мокром полу), `grade` (цветокоррекция кадра: `contrast`, `saturation`, `brightness`, `tint`, `tintAmount`), три слоя (`far`, `mid`, `floor`: `image`, `hd` — та же картинка вдвое крупнее, `parallax`, `width`, `groundAt`, `y`, `blur`, `repeat`, `mirror`, `tint`) и живые эффекты `ambient`. Крупные слои `*.hd.webp` — исходные `*.png`, увеличенные вдвое Real-ESRGAN x2 (модель SceneWorks/real-esrgan-onnx, BSD-3); качество «Среднее» в настройках игры берёт исходные. Сцены: «Крыша под дождём» (`rooftop`), «Серверная» (`server`: стойки с огнями, холодный пар по полу), «Литейный цех» (`foundry`: металл, искры, марево), «Храм в горах» (`temple`: рассвет, туман, лепестки по ветру). Слои нарисованы `paint` из `kit` (описания в `*.paint.json`), листы проверочных кадров — `out/stages-check/`.

`ambient` — список эффектов `{ type, layer, …место, …вид }`, все детерминированы от времени сцены и зерна. Типы: `lights` (мигающие огни), `glow` (пульсирующее свечение), `fog`, `steam`, `sparks` (с тяжестью), `embers`, `wind` (пыль, лепестки, листья, снег), `rays` (лучи света), `heat` (марево). `layer`: имя картинки слоя (эффект живёт в этом слое, с его параллаксом), `back` (за бойцами) или `front` (перед бойцами, гаснет на супере). Место: `area [x0, y0, x1, y1]` или `at [[x, y]…]` в единицах сцены, `uv`/`atUv` в долях картинки слоя, `match { color, tolerance, min }` — эффект садится на яркие точки этого цвета в картинке (огни стоек). Остальные параметры (`count`, `rate`, `size`, `speed`, `alpha`, `color`/`colors`, `life`, `grow`, `gust`…) описаны в начале `kit/arena/render/ambient.js`.

## Реклама

Заготовки для показа спонсора, по умолчанию выключены: `ads/sponsor/ad.json` → `"enabled": false`; в роликах включаются флагом `--ads`, в игре — «Настройки → Реклама». В репозитории лежит нейтральный пример: подставь свой бренд и положи картинки рядом с `ad.json`.

- `costPlate` — плашка «Счёт боя» внизу кадра: строки с суммами задаются руками (`amount`, `fixed: true` — сумма сразу целиком, иначе растёт по ходу боя), валюта, подпись.
- `cardFlip` — после финала карточка проигравшего переворачивается и становится нейтральной виртуальной картой с надписью `label`. Логотип — `ads/sponsor/logo.png`, без файла на карте размечено пустое место.
- `billboard` — щит на дальнем плане крыши (`stages/rooftop/stage.json` → `ads.billboard`: слой, место, размер). Картинка — `ads/sponsor/billboard.png`, без файла щит показывает надпись `label` и `sub`.

## Устройство

- `kit/arena/engine/` — правила, детерминированные и без DOM: 60 тиков/с, случайность только у способностей и с зерном ринга. `constants.js` — все числа, `skeleton.js` — общий скелет и позы, `blocks.js` — основы конструктора и формула цены способности, `fighter.js` — проверка бойца, `sim.js` — бой и то, что видят мозги, `ability.js` — примитивы способности кодом и их пределы, `measure.js` — замер силы способности на манекене, перезарядка и стоимость, `instrument.js` и `meter.js` — загрузка модулей способности со встроенным счётчиком шагов (бюджет хука в шагах, не во времени). Судья, песочница и просмотрщик используют один код.
- `kit/arena/render/` — WebGL-рендер на PixiJS 8: `scene.js` (скелет с частями, слои фона, эффекты, камера, HUD), `broadcast.js` (порядок показа), `show.js` (VS, табло, итог, финал), `abilityfx.js` (объекты, эффекты и ресурсы способностей), `ads.js`, `sound.js` (какой звук на какое событие боя), `seat.js` (посадка частей на кости), `lab.js`.
- `kit/arena/tools/` — `check`, `spar`, `preview`, `look`, `paint`, `parts`, `voice` (с `listen`), лимиты.
- `judge/` — участники и их запуск (`contestants.js`), матч и раздевалка (`match.js`), ролики раундов (`render.js`).
- `viewer/` — просмотрщик судьи, `stages/` — сцены, `announcer/` — ведущий, `ads/` — рекламные заготовки, `prompts/` — промпты участникам.

## Настройка машины оператора

- Node.js 18+, ffmpeg и ffprobe в PATH, Google Chrome или Edge (или `RING_CHROME=<путь>`).
- Codex CLI с входом (`codex login`): им рисует `paint` у обоих участников, им же работает Codex-участник.
- Голос (ElevenLabs): `~/.config/fight-ring/services.env` (или переменные окружения) с `ELEVENLABS_SSH` и `ELEVENLABS_SSH_ENV`. Вариант с сервером: `ELEVENLABS_SSH=<ssh-имя сервера>`, `ELEVENLABS_SSH_ENV=<файл на сервере с ELEVENLABS_API_KEY=…>`, ключ читается только там. Вариант на этой машине: `ELEVENLABS_SSH=local`, `ELEVENLABS_SSH_ENV=<свой файл с ELEVENLABS_API_KEY=…>` вне папок участников, нужен Python 3. `ELEVENLABS_SSH=off` выключает голос.
- Лимиты на участника — `ring.config.json` (`limits`, при необходимости `contestants.<id>.limits`), копируются в `.ring/limits.json` при создании участника. Расход — `node arena/cli.mjs limits` в папке участника.

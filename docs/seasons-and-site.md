# Сезон и сайт

## Сезон

Сезон — это законченный турнир, записанный в репозиторий. Рабочие файлы судьи (`matches/`, `contestants.json`, папки участников) в git не попадают и живут только на машине, где шёл турнир. Сезон переносит из них то, что нужно, чтобы любой человек после клона увидел тех же бойцов и те же бои.

```
node ring.mjs publish 2026-11-gpt-6-2 --matches t51-semi-1,t51-semi-2,t51-final --title "Турнир к выходу GPT-6.2"
```

Команда (`judge/publish.js`) пишет папку `seasons/<сезон>/`:

- `fighters/<id>/v<N>/` содержит каждую отличающуюся версию каждого бойца один раз, в том виде, в каком она стояла в раундах; черновики модели (папки `work` и `out`, сырые генерации `parts/raw`, описания картинок `*.paint.json`) не копируются;
- `matches/<матч>/round-N/replay.json` содержит запись каждого раунда;
- `game.json` содержит карточку сезона, бойцов с версиями и матчи в том же виде, в каком их отдаёт игре сервер судьи.

Роликов в сезоне нет: бой воспроизводится движком из записи. Запись — это зерно, старт и действия обоих бойцов на каждом тике. Тест `tests/season.test.mjs` переигрывает каждый раунд каждого сезона сегодняшним движком и сверяет хэш боя и здоровье в конце. Изменение движка, которое сдвинет старый бой хотя бы на тик, этот тест не пройдёт.

В сезоне `2026-11-gpt-6-2` рядом лежат ещё три файла, которые команда `publish` не пишет: `league.json` и `league.md` с таблицей лиги этого турнира и `spend.json` с расходами моделей.

Повторный запуск `publish` с тем же именем сезона переписывает только своё: `game.json`, `fighters/` и `matches/`. Эти три файла он не трогает.

## Сайт

```
node ring.mjs site dist              # страницы и игра одной командой; первый раз сам ставит зависимости site/ (npm ci)
node ring.mjs site dist --no-pages   # одна игра, без npm
```

Команда (`judge/site.js`) собирает сайт обычными файлами в папку `dist/`. В корне лежат страницы: главная, `tournament/`, `fighters/`, `enter/`, картинки в `assets/`. В `play/` лежит игра из `viewer/`, рядом то, что она читает: части набора (`kit/arena/engine`, `render`, `sounds`, `sparring`, `vendor`, шаблон `kit/fighter`), сцены, ведущий, опубликованные сезоны и файл `api/game.json`.

Страницы написаны на Astro в папке `site/`. Данные при сборке читает один модуль `site/src/data/ring.ts` из `seasons/<сезон>/`, чисел, вписанных руками, на страницах нет. Все ссылки относительные (`site/src/lib/paths.ts`), поэтому за сайтом нет сервера: папку отдаёт любой статический хостинг под любым путём домена. Проверить это можно командой `python3 -m http.server` из папки над `dist/`.

Страницы выглядят как экраны игры: матч показан экраном VS с плашками раундов, лига — лестницей силовых полос, галерея бойцов — экраном выбора бойца. За это отвечают общие стили `site/src/styles/site.css` и два скрипта в `site/public/ui/`, которые Astro кладёт на сайт как есть. `arcade.js` включает звуки меню игры после первого нажатия на странице, показывает блоки с отметкой `data-rise`, когда они доходят до окна, и ведёт выбор бойца; выключатель звука пишет в ту же запись `ring.settings` в `localStorage`, что и настройки игры. `live.js` рисует живых бойцов: он берёт отрисовку фигуры из игры (`play/game/figure.js`) и загружает её, только когда боец подходит к окну, а до этого страница показывает портрет. Картинки частей бойца страницы получают в WebP, их адреса лежат в `ui/rigs.json` (`site/src/lib/rig.ts`). Новой странице достаточно взять готовые компоненты `Figure`, `MatchCard`, `FighterCard` и классы `slab`, `plate`, `tile`, `chip`, `gauge`.

Ссылки со страниц в игру: `play/?match=<матч>&auto=round&round=N` открывает раунд, `play/?screen=play&vs=c/<id>` открывает «Играть самому» с выбранным соперником.

На статическом сайте нет пульта турнира, режима разработчика и рекламных заготовок: за ним нет судьи. Бои воспроизводятся из записей сезона, «Свой бой» и «Играть самому» считаются в браузере.

# Сезон и сайт

## Сезон

Сезон — это законченный турнир, записанный в репозиторий. Рабочие файлы судьи (`matches/`, `contestants.json`, папки участников) в git не попадают и живут только на машине, где шёл турнир. Сезон переносит из них то, что нужно, чтобы любой человек после клона увидел тех же бойцов и те же бои.

```
node ring.mjs publish 2026-11-gpt-6-2 --matches t51-semi-1,t51-semi-2,t51-final --title "Турнир к выходу GPT-6.2"
```

Команда (`judge/publish.js`) пишет папку `seasons/<сезон>/`:

- `fighters/<id>/v<N>/` содержит каждую отличающуюся версию каждого бойца один раз, в том виде, в каком она стояла в раундах; черновики модели (папки `work` и `out`, сырые генерации `parts/raw`, описания картинок `*.paint.json`) не копируются;
- `matches/<матч>/round-N/replay.json` содержит запись каждого раунда;
- `game.json` содержит карточку сезона, бойцов с версиями и матчи в том же виде, в каком их отдаёт игре сервер судьи.

Роликов в сезоне нет: бой воспроизводится движком из записи. Запись — это зерно, старт и действия обоих бойцов на каждом тике. Тест `tests/season.test.mjs` переигрывает каждый раунд каждого сезона сегодняшним движком и сверяет хэш боя и здоровье в конце. Изменение движка, которое сдвинет старый бой хотя бы на тик, этот тест не пройдёт.

В сезоне `2026-11-gpt-6-2` рядом лежат ещё три файла, которые команда `publish` не пишет: `league.json` и `league.md` с таблицей лиги этого турнира и `spend.json` с расходами моделей. Четвёртый файл, `links.json`, называет ролик о турнире (`{ "video": "…" }`): страница турнира ставит на него кнопку.

Повторный запуск `publish` с тем же именем сезона переписывает только своё: `game.json`, `fighters/` и `matches/`. Эти три файла он не трогает.

## Сайт

```
node ring.mjs site dist              # страницы и игра одной командой; первый раз сам ставит зависимости site/ (npm ci)
node ring.mjs site dist --no-pages   # одна игра, без npm
node ring.mjs site dist --no-rating  # без подсчёта общего рейтинга
node ring.mjs site dist --kept-rating  # с таблицей прошлого подсчёта из out/rating.json, без боёв
```

Команда (`judge/site.js`) собирает сайт обычными файлами в папку `dist/`. В корне лежат страницы: главная, `tournament/`, `fighters/`, `rating/`, `enter/`, картинки в `assets/`. В `play/` лежит игра из `viewer/`, рядом то, что она читает: части набора (`kit/arena/engine`, `render`, `sounds`, `sparring`, `vendor`, шаблон `kit/fighter`), сцены, ведущий, опубликованные сезоны, общий набор `roster/` и данные игры: лёгкий список `api/game.json` и подробности по бойцу и по матчу в `api/fighter/` и `api/match/` ([game.md](game.md)).

Перед сборкой страниц команда считает общий рейтинг: последние версии бойцов сезонов, бойцы общего набора и эталоны. Первый подсчёт на девяти бойцах играет 1440 боёв и занимает на ноутбуке несколько минут, дальше играются только пары с новыми бойцами. Таблица попадает на страницу «Рейтинг» и в файл `api/rating.json`. В корень сайта кладётся файл `_headers` с политикой, которая защищает зрителя от мозгов присланных бойцов. Рейтинг и защита описаны в [roster.md](roster.md).

Страницы написаны на Astro в папке `site/`. Данные при сборке читает один модуль `site/src/data/ring.ts` из `seasons/<сезон>/`, `roster/<id>/` и из таблицы рейтинга, чисел, вписанных руками, на страницах нет. Боец, который дрался в нескольких сезонах, имеет одну страницу с боями всех сезонов. Все ссылки относительные (`site/src/lib/paths.ts`), поэтому за сайтом нет сервера: папку отдаёт любой статический хостинг под любым путём домена. Проверить это можно командой `python3 -m http.server` из папки над `dist/`.

Страницы выглядят как экраны игры: матч показан экраном VS с плашками раундов, лига — лестницей силовых полос, галерея бойцов — экраном выбора бойца. За это отвечают общие стили `site/src/styles/site.css` и два скрипта в `site/public/ui/`, которые Astro кладёт на сайт как есть. `arcade.js` включает звуки меню игры после первого нажатия на странице, показывает блоки с отметкой `data-rise`, когда они доходят до окна, и ведёт выбор бойца; выключатель звука пишет в ту же запись `ring.settings` в `localStorage`, что и настройки игры. `live.js` рисует живых бойцов: он берёт отрисовку фигуры из игры (`play/game/figure.js`) и загружает её, только когда боец подходит к окну, а до этого страница показывает портрет. Картинки частей бойца страницы получают в WebP, их адреса лежат в `ui/rig/<боец>.json`, по одному файлу на бойца (`site/src/lib/rig.ts`); те же лёгкие копии берёт игра на сайте. Лестницу с силовыми полосами рисует компонент `LeagueTable`: он один у лиги турнира и у страницы «Рейтинг». Длинный список получает искалку (компонент `Finder`): поиск по имени, модели и автору, отбор по модели и порядок. Она есть в галерее бойцов, когда их больше двенадцати, и на странице «Рейтинг», когда строк больше шестнадцати; работу ведёт `arcade.js` по отметкам `data-finder` и `data-item`. По плиткам галереи можно ходить стрелками. Встроенных обработчиков вроде `onerror="…"` на страницах нет: политика защиты из `_headers` их не исполняет. Новой странице достаточно взять готовые компоненты `Figure`, `MatchCard`, `FighterCard`, `LeagueTable` и классы `slab`, `plate`, `tile`, `chip`, `gauge`.

Ссылки со страниц в игру: `play/?match=<матч>&auto=round&round=N` открывает раунд, `play/?screen=play` и `play/?screen=custom` открывают выбор боя в двух видах («Играть самому» и «Стравить модели» в шапке), `play/?screen=play&vs=c/<id>` ставит бойца соперником, `play/?screen=custom&a=c/<id>` ставит бойца в левый угол («Стравить с…» на странице бойца). В игре, открытой с сайта, на экранах верхнего уровня есть кнопка «На сайт», а Esc на первом экране возвращает на страницу, с которой пришёл посетитель. Экран «Нажми любую клавишу» игра показывает, только если браузер не дал звук без нажатия.

На статическом сайте нет пульта турнира, режима разработчика и рекламных заготовок: за ним нет судьи. Бои воспроизводятся из записей сезона, «Свой бой» и «Играть самому» считаются в браузере.

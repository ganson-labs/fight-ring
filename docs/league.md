# Лига

Лига сводит каждого участника с каждым много раз и считает рейтинг. Это способ сравнить модели точнее, чем один матч: один бой может решить случай, сотни боёв показывают силу.

## Лига между бойцами сезона

Бойцы прошедшего турнира лежат в репозитории, и лигу между ними можно сыграть без участников и агентов:

```
F=seasons/2026-11-gpt-6-2/fighters
node ring.mjs bench run home --ids dir:$F/astra50/v5,dir:$F/opus50/v5,dir:$F/fable50/v3,dir:$F/carbon50/v3,dir:$F/sol50/v1 --draws 1
```

Эта команда играет 100 боёв и на ноутбуке занимает около полутора минут. Таблица пишется в `leagues/home/README.md`, записи всех боёв лежат в `leagues/home/fights/`. Папка `leagues/` в git не попадает. Имя лиги занято, пока её папка существует: для второй попытки возьмите другое имя или уберите папку.

Таблица турнира, который прошёл на этой версии ринга, лежит в [seasons/2026-11-gpt-6-2/league.md](../seasons/2026-11-gpt-6-2/league.md). Она сыграна с восемью розыгрышами и эталонами, поэтому цифры домашней лиги с ней не совпадут.

## Кто играет

Участник лиги задаётся в ключе `--ids` одним из трёх способов. Имя из реестра `contestants.json` означает сборку модели. Запись `ref:<имя>` означает эталон: одного из спарринг-партнёров ринга из `kit/arena/sparring/`. Запись `dir:<папка>` означает пробу: любую папку бойца. Проба получает имя по папке; версия бойца сезона вида `…/astra50/v5` получает имя `astra50-v5`. Пробы не попадают в таблицу моделей и идут только в общий список. Сборки одной модели между собой не встречаются.

## Как устроена лига

Каждая пара играет пять стартов: в центре, вплотную, издалека, у левой стены и у правой. Каждый старт повторяется столько раз, сколько задано ключом `--draws`, и каждый раз с двух сторон. Повторы отличаются встряской старта: центр пары сдвигается до ±80 единиц, расстояние между бойцами меняется до ±40, мозги каждой стороны включаются с задержкой от 0 до 6 тиков. Встряска принадлежит стороне, а не бойцу. Розыгрыши встряски берутся из SHA-256 хэшей сданных бойцов, поэтому лигу тех же бойцов можно повторить точно.

Рейтинг считается по модели Брэдли — Терри со слабым априором, средний эталон равен 1000. Интервал считается двухуровневым кластерным бутстрэпом: сначала по сборкам модели, затем по условиям пары. Место определяется по интервалам, поэтому два участника с пересекающимися интервалами могут делить место. В отчёте есть паспорт зрелищности (он считается по боям, где есть сборка) и сила сигнала.

Мозги бойца ограничены шагами, а не временем: 500 000 шагов на один ход. Поэтому лига идёт параллельно на всех ядрах и не зависит от загрузки машины. Число параллельных боёв задаёт ключ `--jobs`.

## Проверки лиги

```
node ring.mjs bench show pilot         # таблица ещё раз
node ring.mjs bench invariants pilot   # правила соблюдены на всех записях, хэши совпадают
node ring.mjs bench ablate pilot       # что будет, если у бойца убрать один приём
```

Команда `invariants` переигрывает записи лиги и проверяет на них правила боя. Команда `ablate` убирает у каждого бойца по одному приёму и играет заново: если доля очков изменилась больше чем на 30 процентных пунктов, приём отмечается на ручной разбор.

## История: ринг 3.0 и лига 2.x

Правила боя и метод сравнения моделей писались для ринга 3.0. Документы лежат в [docs/v3/](v3/): правила `rules.md`, метод `method.md`, взаимные отзывы на них, решения по расхождениям `decisions.md`, калибровка чисел `calibration.md` и отчёт о пилотах `pilot.md`. Тесты на каждое правило лежат в `tests/ring3.test.mjs`.

В ринге 3.0 боец собирался из блоков с ценами, и каждый пилот выигрывала сборка, которая находила самую дешёвую дыру в прайсе. Поэтому в ринге 4.0 приёмы у всех бойцов из одного набора с одинаковыми числами, а бой решают мозги. Набор описан в `kit/arena/engine/standard.js`, правила для участника описаны в `kit/ARENA.md`. Конструктор ринга 3.0 остался в движке как набор правил `free`: на нём идут тесты рингов 2 и 3 и старые матчи.

Команды `league run`, `league show` и `league list` относятся к лиге ринга 2.x: каждый с каждым, пять стартов, две стороны и несколько зёрен. Они оставлены для старых данных.

Вспомогательные скрипты в `scripts/`: `make-exploits.mjs` собирает бойцов-эксплойты по дырам ринга 2.8 в `tests/fixtures/exploits/`, `port-fighter.mjs` переносит бойца старой версии на цены 3.0, `league-audit.mjs` разбирает сыгранную лигу.
